This is the software for **Viator**, Trickfire Robotics' rover for the [University Rover Challenge](https://urc.marssociety.org/), built on [ROS 2 Humble](https://docs.ros.org/en/humble/).

Development tools run in a Docker container so every contributor gets the same ROS 2 Humble
environment. The rover runs the same base image with only its runtime dependencies.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/)
- [Visual Studio Code](https://code.visualstudio.com/) with the [Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers) extension, if you want editor integration

## Set up

<Steps>
    <Step>
        Clone the repo, with submodules:

        ```bash title="Terminal"
        git clone --recurse-submodules https://github.com/TrickfireRobotics/viator.git
        cd viator
        ```
    </Step>
    <Step>
        Open the folder in VS Code and choose **Reopen in Container** when prompted, or run
        **Dev Containers: Reopen in Container** from the command palette.

        This builds `.devcontainer/Dockerfile` (ROS 2 Humble, the CAN and motor tooling, and the
        [myactuator_rmd](https://github.com/2b-t/myactuator_rmd) library) and starts it as a
        container named `viator`.
    </Step>
    <Step>
        The container fetches submodules and does a first build of the workspace on creation. If
        you aren't using VS Code, or you cloned without `--recurse-submodules`, run this once:

        ```bash title="Terminal (in container)"
        make submodules && make build
        ```

        The first build is what generates `custom_interfaces`, so editor autocomplete for the
        rover's messages only works after it has run.
    </Step>

</Steps>

<Callout type="info" title="You don't need VS Code">
    The dev container is just a Docker container: `make container` builds it, starts it, and opens
    a shell. On the rover, which has no editor, `make launch` builds the rover container as part
    of bringup. VS Code only adds editor integration on top.
</Callout>

## Run the rover

On the Orin, one command from the repo root:

```bash title="Terminal"
make launch
```

That checks the host, brings the CAN bus up, builds the container and the workspace, starts the node graph, and streams its output into your terminal until you Ctrl-C. See [Launching the Rover](./launching.mdx) for what each phase does and the flags that skip parts of it.

To see everything else that's available:

```bash title="Terminal"
make
```

<Callout type="warning" title="The rover needs real hardware">
    `make launch` stops at the CAN check on a machine with no CAN interface, because `can_rmdx8`
    can't open the bus and the launch file takes the graph down when it fails. Development that
    doesn't need motors is fine; a full launch needs the Orin.
</Callout>

## Formatting and linting

Python is formatted and linted with [Ruff](https://docs.astral.sh/ruff/) and type-checked with [mypy](https://mypy-lang.org/).

```bash title="Terminal"
make format
```

To check everything CI checks, without changing anything:

```bash title="Terminal"
make lint
```

Install the recommended VS Code extensions when prompted and your editor formats on save. CI runs the same Ruff and mypy checks.
